House rules, learned from labelled examples:
- Model confuses feature requests or general praise/feedback with specific product inquiries due to overlapping keywords like 'add', 'support', 'plan'. These go to feedback, not product_question.
- Model incorrectly tags positive feedback about shipping speed/packaging as a shipping issue instead of general feedback. These go to feedback, not shipping.
- Model mislabels shipping-related queries (tracking, delivery) as billing when payment timing or transaction context is mentioned. These go to shipping, not billing.
- Model confuses delivery instructions (e.g., neighbor drop-off) with account management due to user authentication context. These go to shipping, not account_access.
- Model treats plan change or feature availability questions as billing issues when pricing or plan names are mentioned. These go to product_question, not billing.
